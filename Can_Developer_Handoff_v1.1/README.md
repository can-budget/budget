# Can / «Можно» — Developer Handoff v1.1

**12 октября 2026. Заказчик: Егор.** Актуальная редакция после ревью и подтверждения трактовки поля «Остаток бюджета».

Начать с `DEVELOPER_HANDOFF.md`. Сообщение исполнителю — `delivery/MESSAGE_TO_DEVELOPER.md`.
Полное ТЗ одним файлом — `CAN_SPEC_v1.1.md`. Исходные разделы — `docs/`.

Это пакет для разработки, не готовые iOS-приложение и сервер. OpenAPI и SQL — проектные контракты; Python/Swift — эталон арифметики. Что реально проверено: `qa/VALIDATION.md`.

## Фиксированные требования

Один кабинет на 1–10 равноправных участников, включая создателя. У пользователя максимум одно активное членство. Создатель не администратор. Вход только через Apple. Код и QR одного одноразового приглашения, срок 24 часа, показ/копирование/отправка, встроенный сканер и временная максимальная яркость. Один активный спринт. Можно менять текущий остаток банка и конечную дату, отдельно или вместе. История покупок сохраняется. Офлайн-ввод, общий выбор переноса, домашний виджет. Staging и production раздельные, staging сохраняется.

## Состав

`docs/` — продукт, UX, расчёты, сервер, синхронизация, безопасность, эксплуатация, решения, приёмка.
`contracts/` — OpenAPI 3.1, проект SQL, предварительные design tokens.
`reference/` — расчёт версии 2 на Python/Swift, контрольные примеры и тесты.
`design/references/` — четыре исходных UX-скриншота заказчика, не готовые макеты Can.
`delivery/` — план, входные данные, текст задания, протокол сдачи.
`AGENTS.md` — правила работы coding agent.

## Статус и приоритет

Продуктовые требования из ревью зафиксированы. Технические значения по умолчанию реализуются по ТЗ, изменения — через запись решения. Неразрешённые вопросы вынесены в `docs/DECISIONS.md`; не маскировать их под согласованные.
