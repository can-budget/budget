# Автоматическое продление SideStore и Can

`Can-Refresh` проверяет подключение к Wi-Fi. Если сеть есть: **LocalDevVPN Enable → ожидание 5 секунд → SideStore Refresh All Apps → LocalDevVPN Disable**. Без Wi-Fi ветка продления пропускается. Новая IPA для продления не нужна; обновляются подписи установленных SideStore и Can вместе с extension.

## Создать и передать команду

На Mac с Xcode, штатной утилитой `shortcuts` и подключённым доверенным iPhone:

```sh
make ios-refresh-send IOS_DEVICE="имя или идентификатор iPhone"
```

Только создать файл: `make ios-refresh-shortcut IOS_DEVICE="..."`.

Генератор определяет фактический bundle ID SideStore на выбранном телефоне и создаёт подписанный Apple файл в `build/ios-refresh/<timestamp>/`. Вариант `--send` копирует его в Documents SideStore. Пароли Apple, pairing и приватные ключи генератор не читает. Стандартная подпись экспорта передаёт Apple публичную структуру команды.

На втором телефоне повторить генерацию с его `IOS_DEVICE`; bundle ID зависит от используемого signing account. Если телефона нет под рукой, можно явно передать известный публичный идентификатор:

```sh
python3 apps/ios/tools/refresh_shortcut.py --sidestore-bundle-id com.SideStore.SideStore.YOURTEAMID
```

Заменить `YOURTEAMID` фактическим десятисимвольным Team ID. Зарегистрированное действие установленной версии SideStore — `RefreshAllIntent`, включая миграцию старого SiriKit intent. Не подменять его именем Swift-типа `RefreshAllAppsIntent`.

## Импортировать и проверить

1. iPhone: **Файлы → Обзор → На iPhone → SideStore → Can-Refresh.shortcut**. Импортировать в «Команды» с заменой прежней версии.
2. Подключиться к Wi-Fi с интернетом и выполнить один ручной запуск. Разрешить обращения к приложениям, если спросит iOS.
3. Проверить успешный refresh **SideStore и Can** и выключение LocalDevVPN. Команда должна завершаться без **All apps have been refreshed / Done**. В параметрах Refresh All Apps переключатель **Show When Run / «Показывать при запуске»** должен быть выключен.
4. При выключенных Wi-Fi и LocalDevVPN повторить запуск: продление должно пропуститься, VPN остаться выключенным. Затем вернуть Wi-Fi.

Если действие не распознано после обновления SideStore, заменить только Refresh All Apps соответствующим действием из каталога установленного приложения. Если VPN подключается медленно, увеличить ожидание до 10 секунд.

## Расписание

На каждом iPhone: **Команды → Автоматизация → Время суток → ежедневно в 03:00 → Can-Refresh**. Выбрать **Немедленный запуск / Run Immediately**, выключить **Уведомлять о запуске / Notify When Run**, если переключатель доступен. Выбрать время, когда телефон обычно находится на Wi-Fi. Расписание создаётся на устройстве и не переносится импортом `.shortcut`.

Ежедневный запуск оставляет запас на пропущенные попытки. Раз в пять дней — слишком редко: после одной неудачи следующая попытка будет на десятый день, за пределами семидневной подписи. Дополнительно можно запускать ту же команду при подключении к Wi-Fi.

Сначала поставить временный запуск через несколько минут, закрыть «Команды», заблокировать экран и дождаться выполнения. После разблокировки проверить журнал/expiry обоих приложений и отключение VPN; затем вернуть ночное время. Ручное выполнение не подтверждает этот фоновый тест.

## Условия и ограничения

- Mac при продлении не нужен. Подходит Wi-Fi с интернетом вне дома; совпадение сети с ноутбуком не требуется. Одной мобильной сети для проверяемого способа SideStore недостаточно. Обычная синхронизация Can работает независимо от LocalDevVPN.
- LocalDevVPN создаёт соединение с сервисами самого iPhone; это не внешний VPN-прокси. Он включается на время обновления подписи.
- В генераторе все App Intent используют `OpenWhenRun=false` и `ShowWhenRun=false`. Собственных уведомлений об успехе и действий открытия приложения нет. Ошибки не скрываются; гарантированной доставки отдельного уведомления об ошибке нет.
- При ошибке Shortcuts останавливает цепочку, поэтому последний Disable может не выполниться. Тогда отключить LocalDevVPN вручную и устранить причину в SideStore. Это не `finally`.
- В проверенной версии SideStore долгий refresh после примерно 27 секунд может запросить продолжение на переднем плане. Полностью незаметное выполнение при любой сети не гарантируется.
- Пропуск без Wi-Fi не продлевает подпись. Семь дней отсчитываются от последнего успешного refresh. После истечения приложение не запустится до восстановления подписи; серверные данные от этого не удаляются.

На первом iPhone подтверждён ручной запуск без Done с отключением VPN. Автоматизация при заблокированном экране, пропуск без Wi-Fi и второй телефон проверяются отдельно.
