# Тихое продление SideStore и «Можно»

Команда `Can-Refresh` проверяет подключение к Wi-Fi. При наличии сети она включает LocalDevVPN, ждёт пять секунд, вызывает **Refresh All Apps** из установленного SideStore и после успешного завершения выключает LocalDevVPN. Без имени подключённой Wi-Fi-сети ветка с VPN и продлением не выполняется. Название сети используется только внутри команды, не записывается и не отправляется на сервер.

Продлеваются активные приложения вместе с их extensions; сам SideStore включён в список последним, поскольку его обновление завершает процесс приложения. Новая IPA «Можно» для обычного продления не нужна. Ноутбук не участвует в продлении: подходит любой Wi-Fi с интернетом, включая сеть вне дома. Одного мобильного интернета для SideStore недостаточно. Работа и синхронизация «Можно» на мобильной сети от этого не зависят.

Основание: [RefreshAllAppsIntent](https://github.com/SideStore/SideStore/blob/6032424a0e56c1c319762e786099bdd9186a238b/AltStore/Intents/App%20Intents/RefreshAllAppsIntent.swift), [выбор приложений и SideStore последним](https://github.com/SideStore/SideStore/blob/6032424a0e56c1c319762e786099bdd9186a238b/AltStore/Core/Model/InstalledApp.swift#L305), [ControlLocalDevVPNIntent](https://github.com/jkcoxson/LocalDevVPN/blob/384b9b8e983461ef3b759e4ab5cde705516dd7d7/LocalDevVPN/VPNShortcuts.swift). Проверяемая конфигурация: SideStore `0.7.0-20260911.328+6032424a`, LocalDevVPN `1.3.0`, iOS `26.7.1`.

В рабочем экспорте с первого iPhone подтверждён зарегистрированный идентификатор SideStore **`RefreshAllIntent`**. Он отличается от имени Swift-типа `RefreshAllAppsIntent` из-за миграции SiriKit/App Intents. Генератор использует идентификатор из экспорта; его публичная структура с тестовой signing identity сохранена в `infra/tests/fixtures/sidestore_refresh_action.json`. Само наличие Swift-типа или успешная подпись файла не подтверждают доступность действия в iOS. На первом телефоне пользователь подтвердил ручной запуск обновлённой команды: refresh завершается без Done, затем LocalDevVPN выключается. Запуск по расписанию с заблокированным экраном и пропуск без Wi-Fi пока отдельно не подтверждены.

## Создать и передать команду

На Mac с Xcode и штатной утилитой `shortcuts`, из корня репозитория:

```sh
make ios-refresh-send IOS_DEVICE="имя или идентификатор iPhone"
```

Телефон должен быть подключён, разблокирован и доверять Mac. Команда читает список developer apps только на выбранном телефоне, определяет фактический bundle ID SideStore после подписи и прекращает работу при неоднозначном выборе. Она не читает Apple Account, пароли, pairing или ключи сертификата.

Генератор хранится в `apps/ios/tools/refresh_shortcut.py`. Результаты находятся в игнорируемом `build/ios-refresh/<UTC timestamp>/`: исходный binary plist, `Can-Refresh.shortcut`, лог валидации и `release.json`. `build/ios-refresh/latest.json` обновляется только после успешной подписи. Apple получает публичную структуру команды для стандартной проверки файла, как при экспорте Shortcut с режимом Anyone; кодов доступа или паролей в нём нет.

Только собрать, без записи на телефон:

```sh
make ios-refresh-shortcut IOS_DEVICE="имя или идентификатор iPhone"
```

Без подключённого телефона можно явно задать известный публичный ID уже установленного SideStore:

```sh
python3 apps/ios/tools/refresh_shortcut.py --sidestore-bundle-id com.SideStore.SideStore.YOURTEAMID
```

`YOURTEAMID` заменить на фактический 10-символьный Team ID. Не использовать ID другого Apple Account. Для второго телефона повторить генерацию с его `IOS_DEVICE`, если установленные bundle IDs отличаются. Создание и передача команды не запускают продление автоматически.

## Импорт и первый тест

1. На iPhone: **Файлы → Обзор → На iPhone → SideStore → Can-Refresh.shortcut**. Открыть файл и подтвердить добавление в «Команды».
2. При импорте заменить прежнюю `Can-Refresh`, если iOS предложит. Проверить структуру: получить **Network Name** сети **Wi-Fi**, условие **has any value**, внутри него LocalDevVPN **Enable**, ожидание **5 секунд**, SideStore **Refresh All Apps**, LocalDevVPN **Disable**, затем **End If**. Если после обновления приложения iOS не распознаёт действие, заменить только его соответствующим действием установленного приложения в редакторе «Команд».
3. Подключиться к Wi-Fi с интернетом. Запустить `Can-Refresh` вручную один раз и разрешить доступ к приложениям, если спросит iOS. Не вводить пароли Apple в текст команды.
4. Команда должна завершиться без окна **All apps have been refreshed / Done**, а LocalDevVPN — отключиться без нажатий. Если окно появляется, раскрыть параметры действия **Refresh All Apps** и выключить **Show When Run / «Показывать при запуске»**. Затем проверить успешное продление **и SideStore, и «Можно»** в My Apps/журнале SideStore, время последнего refresh и срок действия. Один счётчик `7 DAYS` сразу после установки не доказывает, что автоматизация уже выполнилась.
5. Отключить Wi-Fi на телефоне при выключенном LocalDevVPN и запустить команду снова: ветка продления должна быть пропущена, VPN должен остаться выключенным. Вернуть Wi-Fi. Проверку имени сети и её поведение на этом iPhone подтверждает этот тест, а не только статическая структура команды.

Если VPN не успевает подключиться, увеличить ожидание в редакторе до 10 секунд. **Enable/Disable** выбраны вместо Toggle: повторный запуск задаёт состояние явно. При ошибке Shortcuts останавливает цепочку, поэтому завершающий Disable может не выполниться; в таком случае отключить LocalDevVPN вручную, устранить ошибку в SideStore и повторить тест. Команда не обещает семантику `finally`. Не удалять «Можно» с неотправленными операциями.

## Ежедневный запуск

На каждом iPhone создать личную автоматизацию по времени, например ежедневно в 03:00 по местному времени телефона, когда доступен Wi-Fi, и выбрать `Can-Refresh`. Включить **«Немедленный запуск» / Run Immediately**, выключить **«Уведомлять о запуске» / Notify When Run**, если этот переключатель доступен. Разрешить фоновое обновление SideStore в системных настройках. Ежедневный запуск оставляет запас на пропущенные попытки: при расписании раз в пять дней одна неудача отодвигает следующую попытку на десятый день, за семидневный срок подписи.

Дополнительно можно запускать эту же команду по подключению к Wi-Fi: это позволяет выполнить пропущенное продление после возвращения с мобильной сети. Пропуск без Wi-Fi не продлевает подпись: семь дней продолжают отсчитываться от последнего успешного refresh. После истечения срока приложение не запустится до восстановления подписи; серверные данные от истечения подписи не удаляются.

Личное расписание создаётся на устройстве: оно не устанавливается импортом `.shortcut` и не синхронизируется на второй телефон. [Apple: личные автоматизации](https://support.apple.com/en-euro/guide/shortcuts/apd690170742/ios).

Для проверки назначить временный запуск на ближайшие несколько минут, закрыть «Команды», заблокировать телефон и дождаться выполнения на Wi-Fi. После разблокировки подтвердить новый успешный refresh для обоих приложений и вернуть выбранное ежедневное время. Успешное ручное выполнение само по себе не подтверждает фоновое расписание.

## Тихий режим и ограничения

В самой команде нет Show Notification, Show Alert, Open App или Open URL. Все вызовы App Intent имеют `OpenWhenRun=false` и `ShowWhenRun=false`: первый параметр запрещает открытие приложения, второй отключает показ результата действия. Refresh All Apps по умолчанию использует `presentsNotifications=false`, но отдельно возвращает result dialog **All apps have been refreshed**. Поэтому одного `OpenWhenRun=false` оказалось недостаточно: на первом iPhone этот диалог ждал Done и блокировал завершающий Disable. В генератор добавлен `ShowWhenRun=false`; пользователь подтвердил отсутствие диалога и выполнение Disable при ручном запуске на первом телефоне. Проверка запуска по расписанию с заблокированным экраном остаётся отдельной. Системные сообщения об ошибках оставлены; отдельного монитора ошибок или гарантированной доставки уведомления при неудаче нет.

В установленной версии SideStore есть ограничение: после примерно **27 секунд** продолжительного refresh её App Intent запрашивает продолжение на переднем плане и включает уведомление о завершении. Поэтому эта команда не гарантирует полностью незаметное выполнение при любой скорости сети или на заблокированном телефоне. Это поведение стороннего SideStore; команда его не меняет. Если запрос возникает регулярно, фоновый тест не пройден — нельзя считать автопродление настроенным.

Для refresh нужны Wi-Fi и LocalDevVPN; обычное использование «Можно» их не требует. Семидневный предел бесплатной подписи сохраняется. При проблемах pairing или входа SideStore может понадобиться ручное вмешательство. [Требования SideStore](https://docs.sidestore.io/docs/installation/prerequisites), [восстановление pairing](https://docs.sidestore.io/docs/installation/install).

Подписанный файл и статические проверки подтверждают подготовку команды. Работоспособность действий, ручной refresh и автоматический запуск с заблокированным экраном подтверждаются отдельно на каждом телефоне.
